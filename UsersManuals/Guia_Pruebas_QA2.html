Guía de Pruebas QA — Fase 2

Sistema: POS Bar/Restaurante  |  Fecha: 15 de Febrero de 2026  |  Versión: 2.0-QA2

Instrucciones: Ejecutar cada caso de prueba en orden. Para cada test, verificar el resultado esperado. Marcar ✅ si pasa, ❌ si falla, con observaciones.

1. Perfiles de Usuario

Rol Descripción Acceso Principal
ADMIN Dueño/gerente. Acceso total al sistema. Todo: usuarios, caja, POS, inventario, compras, facturas, reportes, configuración
CAJERO Operador de caja y POS. Caja (abrir/cerrar con contraseña), POS (crear orden con contraseña), facturas, ver productos
USER Empleado básico (mesero). Solo ver dashboard y productos. No puede operar caja ni POS.

2. Gestión de Usuarios ADMIN

TEST 2.1 — Crear usuario con indicador de contraseña Crítico

  1. Ir a Usuarios en el menú lateral
  2. Clic en "Nuevo Usuario"
  3. Llenar: Nombre, Email, seleccionar Rol
  4. En el campo Contraseña, escribir "123" → observar indicador
  5. Cambiar a "Abc12345" → observar cambio en indicador
  6. Cambiar a "Abc12345!" → observar indicador verde
  7. Guardar

✓ Indicador de fuerza cambia de rojo → naranja → verde. Muestra qué criterios faltan (mayúscula, número, especial, etc.). Contraseña menor a 8 chars muestra error de validación.

TEST 2.2 — Editar usuario (contraseña opcional) Normal

  1. En la lista de usuarios, clic en editar (ícono lápiz)
  2. Cambiar el nombre
  3. Dejar contraseña vacía
  4. Guardar

✓ Usuario actualizado sin cambiar contraseña. Hint "Dejar vacío para no cambiar" visible.

TEST 2.3 — Eliminar usuario Importante

  1. Clic en eliminar (ícono papelera) de un usuario
  2. Aparece confirmación con el nombre del usuario
  3. Confirmar

✓ Usuario eliminado de la lista.

Nota Backend: Si POST /api/users retorna error 405, el endpoint de creación de usuarios no existe en el backend. Se requiere implementar la ruta.

  1. Iniciar sesión como user
  2. Verificar menú lateral

✓ Visible: Dashboard, Productos (solo ver), Configuración. NO visible: POS, Caja, Facturas, Compras, etc.

TEST 3.4 — Acceso directo por URL bloqueado Crítico

  2. Intentar /cash-register

4. Caja Registradora ADMIN CAJERO

TEST 4.1 — Abrir caja con verificación de contraseña Crítico

  1. Ir a Caja Registradora
  2. Ingresar monto inicial (ej: $100,000)
  3. Clic en "Abrir Caja"
  4. Se solicita contraseña → ingresar contraseña correcta

✓ Caja se abre. Muestra status "Abierta" con monto inicial y desglose de ventas.

TEST 4.2 — Abrir caja: contraseña incorrecta (3 intentos) Crítico

  1. Intentar abrir caja con contraseña incorrecta 3 veces

✓ Tras 3 intentos fallidos: "Sesión bloqueada" y se cierra sesión automáticamente. Redirige a login.

TEST 4.3 — Cerrar caja SIN diferencia Importante

  1. Con caja abierta, ir al panel "Cerrar Caja"
  2. Ingresar monto exacto igual al esperado (Apertura + Efectivo)
  3. Agregar notas opcionales
  4. Clic "Cerrar Caja" → se pide contraseña → confirmar

✓ No se pide motivo de diferencia. Caja se cierra correctamente.

TEST 4.4 — Cerrar caja CON diferencia (faltante) Crítico

  1. Ingresar monto menor al esperado (ej: esperado $200,000, contado $180,000)
  2. Observar alerta "Faltante detectado" en rojo
  3. Intentar cerrar sin escribir motivo
  4. Escribir motivo: "Error de cambio en mesa 3"
  5. Clic "Cerrar Caja" → contraseña → confirmar

✓ No permite cerrar sin motivo. Al escribir motivo y confirmar, caja cierra con nota "Motivo diferencia: ...".

TEST 4.5 — Cerrar caja CON diferencia (sobrante) Importante

  1. Ingresar monto mayor al esperado
  2. Observar alerta "Sobrante detectado" en naranja
  3. Escribir motivo
  4. Cerrar

✓ Misma lógica: requiere motivo si hay diferencia.

TEST 4.6 — User intenta abrir caja Normal

  1. Como user, navegar a /cash-register

✓ Redirige a dashboard (guard de ruta bloquea acceso).

5. Punto de Venta (POS) ADMIN CAJERO

TEST 5.1 — Crear primera orden (guía de bienvenida) Normal

  1. Con caja abierta, ir a POS
  2. Verificar que aparece guía de bienvenida con pasos (1-2-3)
  3. Clic "Crear Primera Orden"
  4. Si no es admin: se pide contraseña

✓ Guía visible la primera vez. Orden se crea tras verificar contraseña (cajero) o directamente (admin).

TEST 5.2 — Bloqueo de nueva orden si hay orden activa Crítico

  1. Con una orden activa abierta
  2. Observar botón "Nueva Orden" en la barra de tabs

✓ Botón "Nueva Orden" está deshabilitado (gris) mientras hay una orden activa seleccionada.

TEST 5.3 — Agregar productos al carrito Normal

  1. Clic en tarjetas de productos de la izquierda
  2. Verificar que aparecen en el carrito derecho
  3. Verificar total se actualiza

✓ Productos se agregan. Total se recalcula correctamente.

TEST 5.4 — Quitar producto del carrito Normal

  1. Clic en ícono de eliminar en un item del carrito
  2. Confirmar

✓ Producto se quita, stock se devuelve, total se actualiza.

TEST 5.5 — Cerrar venta (cobrar) Crítico

  1. Con productos en carrito, clic "Cerrar Venta"
  2. Seleccionar método de pago (Efectivo/Tarjeta/Transferencia/QR)
  3. Confirmar

✓ Venta cerrada. Resumen muestra: orden, total, método, productos, hora. Stock se actualiza.

TEST 5.6 — Cancelar orden con motivo obligatorio Crítico

  1. Con una orden activa, clic "Cancelar Orden"
  2. Aparece campo de texto "Motivo de cancelación"
  3. Intentar confirmar sin escribir motivo
  4. Escribir motivo: "Cliente se fue sin ordenar"
  5. Confirmar

✓ No permite cancelar sin motivo. Al escribir motivo, orden se cancela y stock se devuelve.

TEST 5.7 — POS sin caja abierta Importante

  1. Cerrar caja primero
  2. Ir a POS
  3. Intentar cobrar una orden

✓ Banner "No hay caja abierta" visible. Botón "Cerrar Venta" muestra error "Debes abrir una caja".

TEST 5.8 — Limpieza de estado al navegar Normal

  1. Cerrar una venta (ver resumen)
  2. Navegar a Dashboard
  3. Volver a POS

✓ No aparece resumen viejo. Estado limpio, listo para nueva orden.

6. Facturas ADMIN CAJERO

TEST 6.1 — Crear factura con método de pago Crítico

  1. Ir a Facturas → "Nueva Factura"
  2. Seleccionar cliente
  3. Agregar productos (verificar que solo aparecen activos con stock > 0)
  4. Seleccionar método de pago (Efectivo/Tarjeta/Transferencia/QR)
  5. Crear

✓ Factura creada con método de pago. Productos sin stock no aparecen en selector.

TEST 6.2 — Validación de stock en factura (español) Importante

  1. En nueva factura, seleccionar producto con stock limitado (ej: stock=2)
  2. Poner cantidad mayor al stock (ej: cantidad=5)
  3. Intentar crear

✓ Mensaje en español: "X solo tiene Y unidades disponibles." No crea la factura.

TEST 6.3 — Crear cliente desde formulario de factura Normal

  1. En nueva factura, clic en ícono (+) al lado del selector de cliente
  2. Llenar datos: tipo doc, número, nombre
  3. Campo "Dirección (opcional)" con hint
  4. Crear

✓ Cliente creado y auto-seleccionado en el formulario. Dirección muestra hint "Solo si el cliente lo proporciona".

TEST 6.4 — Detalle de factura (solo admin) Crítico

  1. Como cajero, intentar acceder a /invoices/1
  2. Como admin, acceder a /invoices/1

✓ Cajero es redirigido a dashboard. Admin puede ver el detalle completo.

7. Órdenes de Compra ADMIN

TEST 7.1 — Ver detalle con IVA (19%) Crítico

  1. Ir a Compras → abrir una orden de compra
  2. Verificar tabla de items: columna IVA (19%)
  3. Verificar totales: Subtotal, IVA, Total

✓ Cada item muestra IVA = precio × cantidad × 0.19. Totales correctos al final.

TEST 7.2 — Cancelar orden con motivo Importante

  1. En detalle de orden pendiente, clic "Cancelar Orden"
  2. Aparece campo de motivo (requerido)
  3. Intentar sin motivo → error
  4. Escribir motivo → confirmar

✓ No permite cancelar sin motivo. Tras cancelar, alerta de auditoría muestra quién canceló, cuándo y por qué.

TEST 7.3 — Recibir orden con checklist Crítico

  1. En orden aprobada, clic "Recibir Orden"
  2. Por cada item: marcar checkbox, ajustar cantidad recibida
  3. Si hay devolución: llenar cantidad devuelta + motivo
  4. Confirmar recepción

✓ Checklist interactivo por item. Motivo requerido si hay devolución. Tras confirmar, alerta muestra quién recibió y cuándo.

TEST 7.4 — Auditoría visible en órdenes procesadas Normal

  1. Abrir una orden ya recibida o cancelada

✓ Alerta informativa muestra: acción (recibida/cancelada), usuario, fecha/hora, motivo (si aplica).

8. Inventario y Productos ADMIN

TEST 8.1 — Stock mínimo obligatorio Crítico

  1. Ir a Productos → "Nuevo Producto"
  2. Intentar guardar con stock mínimo = 0

✓ Validación: "Stock mínimo requerido (mín. 1)". No permite guardar con stock mínimo menor a 1.

TEST 8.2 — Filtro stock bajo incluye stock=0 Importante

  1. Marcar checkbox "Stock bajo"
  2. Verificar que aparecen productos con stock=0 y con stock ≤ mínimo

✓ Productos con stock 0 aparecen (chip rojo). Productos con stock ≤ mínimo también aparecen.

TEST 8.3 — Movimientos muestran hora + filas expandibles Normal

  1. Ir a Movimientos de Inventario
  2. Verificar columna "Fecha" muestra fecha Y hora (ej: 15/2/2026 14:30)
  3. Clic en fila expandible (flecha) de un movimiento

✓ Fecha incluye hora. Fila expandida muestra: Usuario y Razón del movimiento.

TEST 8.4 — Ajuste manual de inventario Normal

  1. Clic "Ajuste Manual" → seleccionar producto, nuevo stock, razón
  2. Confirmar

✓ Movimiento tipo "Ajuste" creado. Stock actualizado.

  1. Ir a Proveedores
  2. Verificar panel de alerta amarillo "Productos con stock bajo"

✓ Panel muestra tabla con: SKU, Producto, Stock Actual (chip rojo si 0, amarillo si bajo), Stock Mín., Costo Compra. Solo aparece si hay productos con stock bajo.

TEST 9.2 — Validación email en proveedor Normal

  1. Crear/editar proveedor
  2. Escribir email inválido (ej: "abc")
  3. Intentar guardar
  4. Dejar email vacío → debe permitir

✓ Email inválido muestra "Email no válido". Email vacío es permitido (campo opcional).

TEST 9.3 — Dirección opcional en clientes Normal

  1. Ir a Clientes → crear cliente
  2. Verificar campo "Dirección (opcional)" con hint

✓ Label dice "Dirección (opcional)". Hint: "Solo si el cliente lo proporciona".

10. Flujo Completo: Día Suave (Lunes/Martes)

1 admin opera solo todo el día.

FLUJO 10.1 — Día completo como Admin Crítico

  1. Inicio: Login como admin → Dashboard
  2. Abrir Caja: Ir a Caja → Monto inicial $100,000 → Contraseña → Abrir
  3. Venta 1 (POS): Ir a POS → Crear orden → Agregar 2 productos → Cerrar venta (Efectivo)
  4. Venta 2 (POS): Nueva orden → Agregar 1 producto → Cerrar venta (Tarjeta)
  5. Factura: Ir a Facturas → Nueva factura → Cliente + productos → Método pago → Crear
  6. Inventario: Ver Productos (verificar stock actualizado) → Ver Movimientos (verificar registros de venta)
  7. Compras: (Si hay ordenes pendientes) Recibir con checklist
  8. Cierre: Ir a Caja → Contar efectivo → Ingresar monto → Contraseña → Cerrar

✓ Todo el flujo funciona sin errores. Stock se descuenta con ventas. Movimientos registrados. Caja refleja ventas.

11. Flujo Completo: Día Pesado (Jueves-Sábado)

Admin + 2-3 cajeros operando simultáneamente.

FLUJO 11.1 — Multi-cajero Crítico

  1. Admin: Login → Abrir caja para el turno
  2. Cajero 1: Login (otra pestaña/dispositivo) → Ir a POS → Contraseña → Crear orden → Vender
  3. Cajero 2: Login → Ir a POS → Contraseña → Crear orden → Vender
  4. Admin: Supervisa inventario, crea facturas si necesario
  5. Cancelación: Cajero 1 cancela orden → Escribe motivo → Confirmar
  6. Cierre: Admin cierra caja → Contraseña → Diferencia → Motivo si aplica

✓ Múltiples cajeros pueden operar POS con contraseña. Admin mantiene supervisión. Cancelaciones registran motivo.

12. Seguridad y Verificación

TEST 12.1 — 3 intentos fallidos de contraseña → logout Crítico

  1. En cualquier acción que pida contraseña (abrir caja, crear orden POS)
  2. Ingresar contraseña incorrecta 3 veces seguidas

✓ Mensaje "Sesión bloqueada". Cierre de sesión automático. Redirige a /login.

TEST 12.2 — Inactividad (60 segundos) Importante

  1. Dejar la app sin interacción
  2. A los 50 segundos: advertencia
  3. A los 60 segundos: cierre de sesión

✓ Alerta de inactividad aparece. Si no hay acción, cierra sesión automáticamente.

13. Items Pendientes de Backend

Los siguientes items requieren cambios en el backend (Laravel) que no pueden resolverse desde el frontend:

#ItemDetalle
1POST /api/users → 405El endpoint de creación de usuarios no existe. Se necesita ruta POST en Laravel.
2Sistema de emailNotificaciones por email al admin (errores, alertas). Requiere configuración de correo en backend.
3Foto/evidencia al cerrar cajaUpload de imagen como evidencia del conteo. Requiere endpoint de upload + storage.
4Ventas de facturas en cajaLas ventas por factura no se reflejan en totales de caja registradora (lógica backend).
5Reporte diario con facturasEl reporte diario no incluye ventas por facturas (query backend).
6Reset de contraseñaFlujo de "olvidé mi contraseña" con código por email.
7Logs de actividadRegistro centralizado de acciones del sistema (auditoría general).
Recomendación: Priorizar item #1 (POST /api/users) para habilitar la creación de usuarios desde el frontend, y item #4/#5 para completar los reportes financieros.
